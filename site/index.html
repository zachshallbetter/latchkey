The problem

Your .env files hold the keys to everything

They sit in every project and every worktree, get copied between Macs, and are read by every tool and agent that opens the folder. With Latchkey they hold references instead, which are safe to keep around.

How it works

Import once, then run as usual

Import

Latchkey reads your env file, files each value under its project and environment, and swaps the values in the file for references.

Run

Put latchkey run in front of a command. The values reach the command, not the file, and are hidden if it prints them.

Approve

The first read asks with Touch ID, your Apple Watch or your password, and shows who's asking, from where, to run what.

Built for agents

Let an agent run your project without holding your secrets

Coding agents need your API keys to run tests and dev servers. With Latchkey they run commands through latchkey run and never see a value in a file. You decide what they may use without asking.

Everything else

A home for every key you use

Projects and environments

shop/development, shop/vercel.preview, or shared. Group, filter and act on a whole project at once.

On every Mac

Values live in iCloud Keychain, end-to-end encrypted, on every Mac signed in to your Apple Account.

History

The last 10 values of every item, and deleted items for 30 days. Restore with one approval.

Push to where it runs

Link an environment to Vercel, GitHub Actions, Railway or Fly and push with their own tools. Production asks twice.

Import a hundred files

latchkey import --batch places every value from every project with one approval, and dry-runs first.

A log without values

Every read, change and refusal, with the program, folder and command. Never a value.

Security

Apple's keychain, your approval, nothing in between

Values stay in iCloud Keychain, in Latchkey's own access group, readable only by the signed app. The command-line tool asks the app over a socket only you can open, and the app asks you.

There's no Latchkey server and no account. Values leave the keychain only for a command you approved, a grant you made, or a push you confirmed.

Where it stops

  • Once a command has a value, it can do anything with it. Masking hides exact copies in its output; it can't stop a command that tries to leak.
  • Anything running as you can ask. Keep grants narrow and short, and deny what you don't recognize.
  • Someone with your Apple Account and a trusted device can reach iCloud Keychain.
