Roadmap · November 2026

What would make Latchkey excellent

Latchkey keeps secrets for one person's Macs and the agents running on them. Files hold latchkey:// references; the app holds the values and releases them when a command starts. Below are the gaps between what's built and an excellent tool, by tier.

Guiding rule: values move from the keychain straight to the process that needs them. People approve; agents get references.

  • BuiltCLI: run, check, import, export, environments, grants, rotate, push, log, MCP
  • BuiltMac app: window, import sheet, menu bar, settings, Latchkey for Safari
  • BuiltApproval panel, then Touch ID, Apple Watch or password; grants; a tamper-evident access log
  • PendingA public, notarized release; sync tried end to end on a second Mac

Tier 1

Fix the basics

Things that undercut daily use or trust today.

  • S

    Sign the app with your team

    Built

    Gap: unsigned builds can't use iCloud Keychain, so nothing syncs, and every reinstall makes macOS ask for your login password per item.

    Built: with DEVELOPMENT_TEAM set in App/project.yml, scripts/install.sh signs with your team and lk status reports iCloud Keychain storage. Notarization only matters for sharing builds.

    You
  • S

    CLI starts the app when it isn't running

    Built

    Gap: if the app is closed, every latchkey command fails with “cannot reach the app”.

    Plan: when the socket is missing, launch Latchkey in the background, wait for it to answer, then carry on.

    YouAgents
  • M

    Time-limited grants

    Built

    Gap: when you step away, approval prompts time out and agents stall.

    Plan: grants such as “agents in ~/Projects/site may read these 4 items for 2 hours”, created from the window or from an approval. Each grant appears in Activity and can be revoked.

    Agents
  • M

    “Allow for this project” on the approval

    Built

    Gap: the system sheet can only say yes or no, with one line of context.

    Plan: a Latchkey panel before Touch ID shows who is asking, from which folder and for which command, with Deny, Allow once, and Allow here for 1 hour / today.

    YouAgents
  • M

    Verify callers by code signature

    Gap: the caller chain is process names, which any program can fake, and callers are identified by PID, which can be reused.

    Built: the caller is identified by its audit token and checked by code signature as Latchkey's own tool or not. Next: check the signing team of each parent in the chain (Claude, Cursor, Terminal), which are still named by their files.

    Agents

Tier 1b

Where secrets come from and where they go

Know what each key is for, notice when one leaks, and get to the right place to replace it.

  • M

    Origin and rotation details

    Next up

    Gap: an item is a name and a value. When one leaks, nothing says which service issued it or where to make a new one.

    Plan: record what the Passwords app records for a login, adapted to keys: the service, account or project, the console URL where it's managed, who made it and when, when it was last rotated, and which projects use it. import and the app fill these in where they can (for example from a key's prefix: sk_live_ is Stripe, ghp_ is GitHub).

    YouAgents
  • L

    Leak alerts

    Next up

    Gap: if a key is pushed to a public repo or pasted somewhere, you find out from the provider, if at all.

    Plan: read GitHub secret-scanning alerts for your repos through gh, scan your own repos and history locally (fingerprints only, values never leave the Mac), and match what's found against your items. A match marks the item compromised, notifies you, and shows where it was found.

    You
  • M

    Compromised: replace it in one place

    Built

    Gap: replacing a leaked key means remembering the console, the new value, and every project and service that used it.

    Built: lk rotate ends the grants that cover an item, opens its service's page for a new key, saves what you paste with the old value in history, and pushes to linked environments with --push. lk touched lists what an agent was given.

    You
  • M

    Projects and environments

    Built

    Gap: one flat list doesn't capture that a project has development, staging and production values.

    Built: IDs project/environment/NAME (latchkey://acp/production/DATABASE_URL), import placement from the repo and file name, moving items with their references, project-wide grants, and a service field filled in on import. Next: remote locations (Vercel, GitHub Actions, Fly) recorded alongside local files.

    YouAgents
  • L

    Remote machines and services

    Built

    Gap: values are needed on servers, in CI and in hosted environments, and today they're copied by hand.

    Built: link an environment to Vercel, GitHub Actions, Railway or Fly; names-only status; push with approval every time and an extra confirmation for production; out-of-date tracking. Also built: forward the Latchkey socket over SSH, so a command on another Mac asks you on yours.

    YouAgents
  • M

    Version history and recovery

    Built

    Gap: a changed or deleted value was gone, and a file rewritten to references could lose its only copy.

    Built: the last 10 values of each item, Recently Deleted for 30 days, restore with approval, synced like the items.

Tier 2

Built for agents

Where Latchkey can be clearly better than a .env file or a password manager.

  • M

    Use a value without holding it

    Gap: “agent-safe” means the agent can hold the value: it can call latchkey get, and masking only catches exact copies.

    Plan: refuse get to agent callers, and mask base64, URL-encoded and JSON-escaped copies too.

    Agents
  • M

    MCP server

    Built

    Gap: agents learn Latchkey from instructions and shell commands.

    Built: latchkey mcp with tools for status, listing items, checking and running a command with references filled in, the checkout's project, writing an env file of references, and asking for a grant. No tool returns a value.

    Agents
  • M

    Secret requests

    Gap: to add a key, an agent has to handle the value or ask you to do it out of band.

    Plan: the agent asks for STRIPE_KEY for this project, a notification opens a field in the app, you paste the value, and the agent gets back only the reference.

    AgentsYou
  • S

    Agent setup kit

    Gap: every agent needs to be told how to use Latchkey, and nothing stops it from running cat .env.

    Built: the Latchkey skill and Claude Code plugin tell an agent to run through lk run, never print values, and stop on 77 or 66. Next: a hook that blocks commands like cat .env and printenv.

    Agents
  • L

    Rules beyond one switch

    Built

    Gap: agent-safe is one yes/no per item.

    Built: grants per folder and its worktrees, for a time, until the agent quits, for one command or one request, e.g. lk grant shop/development/DATABASE_URL --command "npm test".

    AgentsYou
  • L

    Header-injecting proxy

    Built

    Gap: any value in a process's environment can be printed or written to a file.

    Built: lk run --proxy gives the command a placeholder and a local base URL, and adds the real OpenAI or Anthropic key only to requests for the provider's host. Next: more providers.

Tier 3

Day-to-day use

Smaller features that remove friction.

  • M

    Key files

    Built

    Gap: tools that want a file path (.p8, .pem, service-account JSON) can't use an environment value.

    Plan: GOOGLE_APPLICATION_CREDENTIALS=latchkey-file://gcp-sa writes a 0600 temporary file and deletes it when the command exits.

    YouAgents
  • M

    Project commands

    Gap: there's no standard way to set up a project or check it in CI.

    Built: latchkey check confirms what a run would get without reading values, and latchkey export writes an env file of references from the environment's record. Next: latchkey init and a shell hook.

    YouAgents
  • M

    Last used, expiry and rotation

    Gap: nothing says which tokens are stale, unused or about to expire.

    Plan: last-used dates from the log, an expiry date per item, reminders before expiry, and a list of items nothing has read in 90 days.

    You
  • M

    Items with fields

    Gap: AWS and database credentials come in sets that are stored as unrelated items.

    Plan: group items such as aws.access_key_id and aws.secret_access_key as one card with fields.

    You
  • M

    Scan for plain-text secrets

    Gap: secrets already sitting in repos and old .env files stay there.

    Plan: latchkey scan finds likely secrets and offers to import them, plus a git pre-commit hook.

    YouAgents
  • S

    Activity alerts

    Gap: denied or unusual reads are only visible if you open Activity.

    Plan: notifications for denials and first-time callers, and filters by item, folder and outcome.

    You

Tier 4

Moving in

Getting existing secrets into Latchkey, and getting them back out safely.

  • S

    Import from Passwords

    Gap: tokens you've saved in the Passwords app can't be read by other apps.

    Plan: read a Passwords CSV export (File > Export), pick the entries that are really API tokens, import them, then delete the CSV.

    You
  • M

    Import from other managers

    Gap: secrets in 1Password or Bitwarden have to be copied over one by one.

    Plan: importers that use the op and bw command-line tools.

    You
  • M

    Encrypted backup

    Gap: until the app is signed, the login keychain is the only copy, with no recovery.

    Plan: an export encrypted with a passphrase, and a matching restore.

Later

Outside the plan

Limits and non-goals

Items in the Passwords app

Apple doesn't let other apps write to or read from the Passwords app. Latchkey uses the same iCloud Keychain underneath, in its own group. CSV import is the bridge.

Passkeys as API tokens

A passkey only signs logins for one website. Latchkey uses the same Touch ID check for approvals, and Secure Enclave keys for SSH.

Teams and other platforms

Latchkey is for one person's Macs. Shared vaults, Windows and Linux are out of scope.
