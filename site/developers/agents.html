Agents and MCP

Coding agents need your keys to run tests and dev servers. With Pistachio they get them through pistachio run: the values reach the command, not the agent’s files, and you decide what an agent may use without asking.

The pattern

  1. Keep references in env files: pistachio import .env.local --rewrite.
  2. Run anything that needs secrets through pistachio run.
  3. Decide what an agent may read without you: agent-safe items for values that aren’t secret, grants for a folder and a time. Everything else asks you, showing the agent’s process chain, folder and command.

Fresh git worktrees don’t have your .env (it’s gitignored). pistachio run --env PROJECT/ENV loads an environment’s items directly, and a grant for a repository’s folder covers its worktrees.

Skills and plugins

The Pistachio skill tells an agent to run commands through pst run, check before a slow run, never print or write a value, put references in env files, give you the pst set command for a missing key, suggest a session grant when you step away, and stop on 77 or 66.

  • Claude Code: the plugin installs the skill and registers pst mcp as an MCP server. ~/.local/bin must be on the PATH Claude Code starts with.
  • Codex CLI, Gemini CLI, Cursor and other tools that read the Agent Skills format: copy the plugins/latchkey/skills/latchkey folder into the skills folder your tool reads, such as .agents/skills/ for Codex.
  • Claude Desktop and other MCP clients without a shell: add pst mcp as a local MCP server. Chat apps that only reach MCP servers on the internet can’t use Pistachio, since its MCP server runs on your Mac.

The repository is public, so the marketplace install should work, though it hasn’t been tried end to end yet. You can also add the plugin from a local checkout with /plugin marketplace add /path/to/pistachio.

Instructions for agents

Without the skill, put this in CLAUDE.md, AGENTS.md or your agent’s equivalent:

Exit codes to act on

CodeMeaningWhat an agent should do
0Done
64Wrong usageFix the command
66No item with that IDStop; ask the person to add it
69The Pistachio app can’t be reachedStop; ask the person to open Pistachio
73A file couldn’t be rewrittenStop and report
77Refused: not agent-safe, not approved, no grantStop; ask the person to approve or grant. Don’t retry
127The command couldn’t startFix the command

On 77 and 66 the message names the items and, for 77, the exact pistachio grant command that would allow them, for the person to run.

Leaving an agent working

Run them inside the agent’s session (in Claude Code, start the line with !) so --session ties to the agent. The agent’s reads go through without asking until the grant ends, and each one is in the app’s Activity. End it early from Grants in the app or with pistachio revoke ID.

Keys an agent can use but never read

For OpenAI and Anthropic keys, pistachio run --proxy (or proxy: true on pistachio_run) gives the command a placeholder and a local base URL, and adds the real key only to requests to the provider. An agent’s command can call the API but can’t print, encode or send the key anywhere else. See --proxy.

Only the command and the processes it starts can use the proxy; a request from any other program gets a 403, and the proxy stops when the command exits. To narrow what the command may do with the key, add --proxy-models A,B (only requests naming a listed model are forwarded) and --proxy-requests N (refuse requests after N). On pistachio_run these are proxy_models, an array of model names, and proxy_requests, a number; both need proxy: true. Pistachio says on standard error that the limits are enforced.

From another Mac over SSH

Forward Pistachio’s socket when you connect, then point pistachio on the other Mac at it:

$USER expands to your login name on each Mac: use the same name on both, or put a fixed name in both commands. Forwarding needs the direct-download app on your Mac; the Mac App Store version doesn’t support it yet, and if the other Mac has the App Store version installed, set PISTACHIO_BROKER=direct there.

  • Each read that is not agent-safe asks. Your Mac sees only your ssh client, so grants don’t apply and can’t be made over the connection.
  • The approval panel says so, and shows what the tool on the other computer says it’s running, marked as unchecked.
  • The tool there can’t check the app’s signature through a forwarded socket; pistachio status says so.
  • The other computer needs pistachio too; the tool is macOS only.

Pistachio’s MCP server

pistachio mcp gives agents Pistachio’s tools over MCP: for clients without a shell, like Claude Desktop, and for structured refusals instead of exit codes. It has no direct secret-read tool. Child output masks exact secret values; transformed secrets can still leak.

ToolWhat it doesAsks you?
pistachio_statusWhere values are kept, how you approve, item and grant countsNo
pistachio_listItem IDs with kind, service and agent-safe, by project or environment. Never valuesNo
pistachio_checkWhat a run would get without asking, what would ask, and what’s missing, for env_files, environments, files or idsNo
pistachio_runRuns command (an argument array) in cwd with references filled in. Returns the exit code and the output, masked. With proxy, proxy_models and proxy_requests limit what the command may do with the key (see above)When an item isn’t agent-safe or granted
pistachio_request_grantAsks you for a grant on ids in the agent’s folder for durationAlways
pistachio_projectWhich project the folder’s checkout is, from its Git remotes, and its environmentsNo
pistachio_export_referencesWrites an environment’s env file of references and plain settings, never values, inside its cwd onlyNo
  • Output is always masked, and only the last 64 KB of each stream is returned, with a flag when it was cut. Standard input is empty.
  • Commands stop after timeout_seconds: 600 by default, at most 3600. Use it for tests, builds and scripts; run dev servers in a shell with pistachio run. A cancelled request stops its command.
  • Grants an agent asks for cover only the folder it runs in (and that repository’s worktrees), last for the time it asked for (which you see and approve), end when the agent quits, and can’t include production environments or a whole project. Grant those yourself with pistachio grant.
  • Approval panels for requests through the MCP server say they come from an agent.
  • Several requests in a row from the same agent in the same folder share one panel while it’s up, and one touch answers them; a grant until the agent quits stops the asking for the rest of the session.
  • Reading values, changing or deleting items, earlier values, remote locations and pushes aren’t offered.

A refusal is a tool error (isError: true) whose structuredContent has error (refused, missing, unreachable, usage), the ids, and for a refusal the grantCommand for the person to run.

Other MCP servers

An MCP server that your agent starts as a command can get its keys through Pistachio: wrap the command, and keep references in its environment.

  • Use --no-masking: MCP speaks over standard output, which must pass through untouched.
  • The server’s process chain includes the agent, so make its items agent-safe or grant them, or each start asks.
  • Servers reached over HTTP with a header can’t be wrapped this way.

Agents need the absolute path when ~/.local/bin isn’t on their PATH: use "command": "/Users/you/.local/bin/pistachio".

Key files

The command gets the path of a temporary file only you can read, deleted when it exits. In an env file, ASC_KEY_PATH=pistachio-file://shop/production/ASC_P8 does the same.

What Pistachio can’t do for you

A value you release to a command is in that command’s memory and environment. A command run by an agent can write it to a file, send it over the network, or encode it so masking doesn’t catch it. Masking only hides exact copies, 6 characters or longer, in what the command prints. Agent-safe and grants decide what reaches the command; they can’t control what the command does with it.
