Quickstart

From an env file full of secrets to a command that gets them at start-up, in four steps.

On this page

  • 1. Install
  • 2. Import an env file
  • 3. Run a command
  • 4. Let an agent work

1. Install

Download Latchkey-VERSION.pkg from the latest release and open it. The Installer asks for your password once, installs Latchkey in Applications and links ~/.local/bin/latchkey, and lk for short, to the copy inside the app so they update with the app. When it closes, Latchkey opens a short welcome that checks ~/.local/bin is on your PATH (with the line to add if it isn't) and offers the Safari extension, the command that connects Claude Code, and a first .env import.

To drag it in instead, open the disk image from the same release, drag Latchkey to Applications and open it; the welcome offers Install Command Line Tool (also Latchkey › Install Command Line Tool…). Or install with Homebrew: brew tap zachshallbetter/latchkey, brew trust zachshallbetter/latchkey, then brew install --cask latchkey, which puts latchkey and lk in Homebrew's own bin.

You should see storage: iCloud Keychain storage (sync status not verified).

2. Import an env file

Look first. A dry run prints names and where each would go, never values:

Then import, and replace each value in the file with its reference. The project is named after the repository; the environment comes from the file name (.env.local is development).

Imports support quoted multiline values and refuse malformed syntax before saving anything. Rewriting replaces the complete assignment and stops if the file changed while approval was pending.

Every project at once: latchkey import --scan ~/Projects --dry-run, then again without --dry-run. Or latchkey import --batch files.txt, one path per line. Either way, one approval. See the import options.

3. Run a command

Reads ask unless a grant or the No Approval setting permits them. Values that reach the command’s output are replaced with <concealed by latchkey>. The command’s exit status becomes latchkey run’s.

4. Let an agent work

Before you step away, allow the folder for a while. Commands run from it, its subfolders and the repository’s worktrees read these items without asking until the grant ends.

Then tell the agent how to run things; see instructions for agents.
