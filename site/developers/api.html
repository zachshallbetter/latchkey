References and API

The formats Latchkey reads and writes: references in your files, the protocol between the command-line tool and the app, and the files it keeps on disk.

On this page

  • References
  • The broker protocol
  • The access log
  • Files and storage

Use the command-line tool. latchkey is the supported interface, from any language. The socket protocol below is how it talks to the app; it changes only by adding optional fields, but scripts that speak it directly also take on its approval rules.

References

FormWhereBecomes
latchkey://IDValues in env files and in the environment of latchkey runThe item’s value
latchkey-file://IDValues in env files and in the environment of latchkey runThe path of a temporary file holding the value, mode 0600, deleted when the command exits

A latchkey:// reference can sit inside a longer value, as in postgres://app:latchkey://shop/production/DB_PASSWORD@db/shop; each one is replaced. A latchkey-file:// reference must be the whole value. ID is NAME or project/environment/NAME, each part letters, digits, _, - and ., at most 64 bytes.

The broker protocol

The app listens on a Unix socket at ~/Library/Application Support/Latchkey/broker.sock, mode 0600 in a 0700 folder. A client connects, writes one JSON object followed by a newline, and reads one JSON object followed by a newline. Keys are sorted; dates are ISO 8601. Requests say nothing about their caller. The broker asks the kernel instead: the caller’s working folder, command line and parent processes, and, by code signature, whether it’s Latchkey’s own command-line tool. The approval panel and the log show those, and grants are matched against the real folder. A signed latchkey also checks that the socket belongs to the Latchkey app before it sends anything.

Requests are handled one at a time. A request that needs approval waits until you answer, so allow for that in timeouts.

Responses

Every response has ok. When it’s false, error says why: bad input, a change you didn’t approve, a keychain failure. Reads report per item instead: get answers ok: true with denied for items you refused and missing for IDs that don’t exist, and if anything was denied, no values are released at all. The command-line tool maps these to exit codes 77 and 66.

The access log

~/Library/Application Support/Latchkey/access.jsonl, mode 0600: one JSON object per line for every read, change and refusal. Never values.
