Features

A credential manager built for how software actually uses credentials.

Credentials that have IDs, history and a home outside any one project. Env files that hold references. Environments that rebuild on another Mac. Commands and agents that use values only when you've said so, and a record of every time they did.

Credentials

Every credential has a name, a place and a past.

An item is project/environment/NAME, or just NAME when it's shared by every project. Its kind, service and note travel with it, and replacing its value keeps the old one.

The Latchkey window, with example data. With scripts on, it works: search, filter by type or environment, pick a project or service in the sidebar, and open an item. It lists:

  • shop: DATABASE_URL, STRIPE_KEY, PGHOST and NEXT_PUBLIC_SITE_URL for development; DATABASE_URL for preview, not pushed yet; DATABASE_URL and STRIPE_KEY for production, the key changed since its last push
  • blog: ADMIN_PASSWORD, SENTRY_DSN and GITHUB_TOKEN
  • api: the ASC_P8 key file and API_BASE_URL
  • Shared: OPENAI_API_KEY and ANTHROPIC_API_KEY

Opening an item shows its value (hidden until Touch ID), reference, type, access, service, project, environment, note, location, history and recent activity. Review lists what may need a look.

The Latchkey window, working with example data: search, filter by type or environment, pick a project or service, and open an item to see its reference, access, location, history and recent activity. Revealing or copying a value asks for Touch ID. The values are made up.

Store and organize In this build

Tokens, passwords, key files and plain values, grouped by project and environment in the app and the CLI. The value is read from standard input or a hidden prompt.

lk set shop/development/STRIPE_KEY --kind token --service Stripe
Items

Share one value across projects In this build

Importing many projects at once, a key with the same value everywhere becomes one shared item that every file refers to. Rotating it is then one change.

lk import --scan ~/Projects --share-identical --dry-run
Importing

Move between environments In this build

Values, settings and history move together, and the references in the files they came from are updated.

lk mv OPENAI_API_KEY --to shop/development
Moving items

History and restore In this build

The last 10 values of each item, and deleted items for 30 days. History lists when and why, never values; Forget History deletes old values for good.

lk history shop/development/STRIPE_KEY
lk restore shop/development/STRIPE_KEY --version 1
History

Find duplicates and combine them In this build

One approval compares values inside Latchkey and says what to do: give production its own key, or combine the rest into one shared item. Files follow, and the originals go to Recently Deleted.

lk duplicates
lk combine shop/development/STRIPE_KEY blog/development/STRIPE_KEY --into STRIPE_KEY
Duplicates

Catch plain values before a commit In this build

lk scan finds env files that still hold a stored value or something that looks secret, and prints file, line and item, never the value. The pre-commit hook refuses those commits.

lk scan ~/Projects
lk scan --install-hook

Environments

References in your files. Values in Keychain.

Each environment has a record of its variables: each points at an item or holds a plain setting like PORT=3000. Records sync with your items, so a checkout anywhere can get its env file back.

Import, then rewrite

The dry run shows where each value goes and sends nothing. One approval saves them, and --rewrite puts a latchkey:// reference where each value was. Comments, order and file permissions are kept.

Import one file or every project In this build

The project comes from the repository's folder, the environment from the file name. Each line is classed as a secret, a setting, a public value or an existing reference: settings like PORT stay in the file, public values are saved plain, and anything unclear is a secret.

lk import --scan ~/Projects --agent-safe-pattern 'NEXT_PUBLIC_*' --dry-run
Importing

Run without a file In this build

--env loads the environment's record, which suits a fresh worktree with no .env. Key files arrive as a temporary path only you can read.

lk run --env shop/development -- npm test
lk run --file ASC_KEY_PATH=shop/production/ASC_P8 -- fastlane beta
Running commands

Export an env file In this build

Writes the environment's file from its record, or --merges into the one you have, keeping comments, order and other variables. --values --clipboard copies an env block for a dashboard; it asks every time and clears after 60 seconds.

lk export shop/development --out .env.local --merge
Export

Recognize a checkout In this build

A project is linked to its Git remotes, so a clone under any folder name knows which project it is. A match only names the project; it never releases a value or widens a grant.

lk project link shop
lk project

Devices

The environment travels with the project. The credential stays in your vault.

Values, versions, environment records and project links are keychain items in Latchkey's own access group. iCloud Keychain carries them, end to end encrypted, to every Mac signed in to your Apple Account that has Latchkey installed.

Clone, export, run

On the next Mac the environment record is already there: lk project recognizes the clone and lk export writes its env file. Grants stay on the Mac where you made them.

Signed app access In this build

Only the signed Latchkey app can read its keychain group. The lk tool never touches the keychain; it checks the app's signature before sending anything.

Forward the app's socket. Each read without the No Approval setting asks you on your own Mac; local grants don't apply over the connection.

export LATCHKEY_SOCKET=/tmp/latchkey-$USER.sock

The direct download checks for updates with Sparkle, or install and upgrade with Homebrew. It sends no system profile; the Mac App Store version updates through the store.

Agents and tools

Grant access for the task. Revoke it when the task is done.

Agents run commands through lk run. You decide what reaches those commands: agent-safe items, grants for a folder and a time, or an approval each time.

Ask, allow, and ask again when it matters

The panel shows the agent, the programs it runs through, the folder and the command, all from macOS. A folder grant until the agent quits covers its next runs; a production item isn't covered, so it asks.

Grants with limits In this build

For a folder (and its repository's worktrees), for up to 7 days, until the agent quits, for one command, or for one request. Kept where only Latchkey can change them.

lk grant 'shop/development/*' --session --for 4h
lk grant 'shop/development/*' --command "npm test" --for 2h
Grants

Check before a slow run In this build

What a run would get without asking, what would ask you, and what's missing. Asks nothing, releases nothing.

lk check --env shop/development
lk check

MCP server In this build

Status, list, check, run, project, export references and request a grant, for clients without a shell. There's no secret-read tool; grants it asks for cover only its own folder, for a day at most, never production.

claude mcp add latchkey -- ~/.local/bin/latchkey mcp
Latchkey's MCP server

Skill and plugin Pending

The Latchkey skill tells an agent to run through lk run, never print values, and stop on 77 or 66. It works from a local checkout; the marketplace install works once the repository is public.

/plugin marketplace add /path/to/latchkey

Masked output In this build

A value of a secret kind, 6 characters or longer, that the command prints becomes <concealed by latchkey>, even split across chunks. Transformed values aren't caught.

Integrations

From the dashboard where a key is made to the platform that runs it.

Save a new key from the page that shows it, push values to deployment platforms with their own tools, and keep some keys out of the command entirely.

Capture credentials when they're issued

When a provider shows you a new key, Latchkey for Safari can recognize it and offer to save it: a Save to Latchkey button sits on the box that holds it. You choose what to save, where it goes and its name; approve, and the panel gives you the reference to use. Spotting happens in the page and nothing leaves it until you press Save. Detection depends on page permissions and supported patterns.

Deployment platforms In this build

Link an environment to Vercel, GitHub Actions, Railway or Fly, see names missing on either side, and push with each service's own tool. Every push asks; production needs a second confirmation. Pushes run in the app.

lk remote link shop/production fly app=shop-api
lk remote status shop/production
lk push shop/production --dry-run
Remote locations

Fill a field from Latchkey In this build

In a field that takes a key, a badge offers the items that may be filled on that site: the item's service and the deployment platforms, or the sites you choose. Touch ID every time.

lk update shop/production/PAYMENTS_KEY --fill-sites vercel.com
lk update

Key proxy In this build

OpenAI and Anthropic keys stay in lk run; the command gets a placeholder and a local base URL, and the real key goes only to the provider's host. It serves only the command and what it started, and can limit models and requests.

lk run --proxy --proxy-models gpt-5 --proxy-requests 50 --env shop/development -- npm test
--proxy

Short-lived AWS credentials In this build

STS credentials that expire after 15 minutes by default, while the long-lived key stays in Latchkey. MFA isn't supported yet.

lk run --aws-role arn:aws:iam::123456789012:role/dev -- terraform plan

Visibility

Know what read what, and prove the record wasn't edited.

Every read, change, grant, move, import and push is logged with the program chain and folder, never a value. Each entry is chained to the last, so an edit or deletion shows.

History, the log and its check

lk history lists earlier values by when, why and who. lk log --verify checks the access log's chain and names the first line that isn't as Latchkey wrote it.

Terminal — ~/Projects/shop
~/Projects/shop $ lk history shop/development/STRIPE_KEY1   Nov 11, 2026 at 3:20 PM  replaced  by zsh › TerminalKept: the last 10 per item. `latchkey restore shop/development/STRIPE_KEY --version N` puts one back.~/Projects/shop $ lk log --verifyintact: 412 signed entries

After an agent session In this build

Every key released to programs an agent started, from the access log, then a guided rotation that ends the grants covering them.

lk touched --since 4h --by claude
lk rotate --touched --since 4h --by claude --open
Rotating

Activity and the menu bar In this build

Every request in the app's Activity, with what asked and from where; the menu bar panel shows the latest and searches your items. The same log is in the terminal.

lk log --limit 20
The app

Expiry and provider-side usage Pending

Latchkey records what it released, not what a service saw. Expiry dates, validity checks and provider-side usage aren't tracked yet; until they are, a note on the item can carry the date.

lk update shop/production/STRIPE_KEY --note "expires March 2027"
